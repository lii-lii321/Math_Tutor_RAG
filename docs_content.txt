===== 提升分析 =====
GitHub 上这个仓库我已经按当前 main 分支做了一轮源码级阅读。它现在其实已经不是一个简单的“RAG Demo”，而是一个视觉大模型 + 错题本 + RAG + SM-2 + Agent/MCP + FastAPI + 教师端的完整雏形：仓库目前约 100 次提交，代码已经拆成 frontend / api / backend / tests / migrations 等层。(GitHub)
先给你一个核心判断：
这个项目当前最值得继续优化的，不是“再加几个页面/功能”，而是把已经存在的功能真正做深：尤其是 RAG 检索质量、数学答案可靠性、异步任务架构、学习画像、权限/多租户和生产部署。
而且我发现了几个可以直接进入下一批开发任务的具体问题。

二、第一优先级：RAG 需要做一次真正的升级
这是我认为目前最值得你继续投入的地方。
当前 RAG 虽然已经有：
Vector → Keyword → RRF → 可选 Rerank
但实现仍然比较初级。
当前 ChromaDB 的核心检索逻辑实际上是：
collection.query(
    query_texts=[query_text],
    n_results=top_k + ...
    where=where,
)
默认 rag_top_k=3。
而且向量入库时，是把：
知识点
+
解析
+
答案
+
易错原因
+
标签
直接拼成一大段文本：
_embeddable_text()
再整体 embedding。
这对于 MVP 可以，但对于数学错题系统有明显问题。
2.1 最大问题：你现在的“知识”实际上没有被结构化检索
比如一道题：
已知函数 f(x)=... 求导数……
当前向量里面实际上类似：
导数
函数极值
单调性
解析过程
答案
易错原因
标签
全部混在一个 embedding 中。
这会导致：
问“找类似题”
可以。
但如果用户问：
“给我找几道和导数定义有关，但不要涉及极值的题。”
当前 RAG 就比较困难。
三、建议升级成“数学知识多路检索”
我建议未来 RAG 变成：
                    用户查询
                       │
          ┌────────────┼────────────┐
          ↓            ↓            ↓
       Dense          BM25       Metadata
      Semantic        Keyword      Filter
          │            │            │
          └────────────┼────────────┘
                       ↓
                     RRF
                       ↓
                  Candidate 20~50
                       ↓
                  Cross Encoder
                     Rerank
                       ↓
                  Top 5~10
                       ↓
                LLM Context
这比现在：
Vector Top3
+
Keyword
+
RRF
要成熟很多。
实际上你现在已经写了 RRF 和 rerank 的接口，所以并不需要推倒重来。fusion.py 已经存在 RRF 和 rerank 钩子。
四、这里还有一个非常值得修的 RAG 实现问题
我特别建议你让 Codex 检查这一块。
在 QueryMixin.list_questions() 中：
primary = repo.list_for_user(... limit=limit)
vector_hits = self.vector_store.semantic_search(...)
fused_ids = rrf_fuse(...)
随后 rerank：
docs = [
    results[qid].content_markdown
    for qid in fused_ids
    if qid in results
]
然后才去数据库加载：
new_ids = [qid for qid in fused_ids if qid not in results]
也就是说：
Vector Retrieval
       ↓
RRF
       ↓
Rerank
       ↓
才加载一部分 vector-only 文档
这会导致：
Reranker 实际上不能完整看到所有候选文档。
源码可以直接看到这一流程。
正确逻辑应该变成：
Keyword Top 50
      +
Vector Top 50
      ↓
RRF Top 30
      ↓
数据库批量取出 Top 30
      ↓
Reranker Top 10
      ↓
最终结果
而不是现在：
数据库已有结果
      ↓
Reranker
      ↓
再补 Vector 结果
这是一个很具体、值得修的检索 pipeline 问题。
五、RAG 不应该只有“题目相似”，应该增加知识点图谱
你现在已经有：
知识图谱（标签共现网络）
但目前本质上更接近：
标签 A ─── 标签 B
   │
   └──── 标签 C
这还不是真正的数学知识图谱。
可以升级为：
             导数
              │
       ┌──────┼──────┐
       ↓      ↓      ↓
    导数定义  单调性  极值
       │             │
       ↓             ↓
   导数计算       最值问题
                       │
                       ↓
                   函数综合
然后每道错题关联：
Question
   ↓
KnowledgePoint
   ↓
Prerequisite
   ↓
RelatedKnowledge
这样才能真正实现：
“你不会极值，是因为导数基础掌握不牢。”
这是这个项目从：
错题本
升级成：
AI 学习系统
的关键一步。

十、第四优先级：SM-2 可以升级成真正的“自适应学习系统”
现在的复习算法是比较标准的简化 SM-2：
again → 0
hard  → 3
good  → 4
easy  → 5
然后计算：
ease
interval
due_at
源码本身比较干净，也容易测试。
但是：
现在它还是“题目级 SM-2”，而不是“知识点级学习模型”。
例如学生：
导数
  ├── 导数定义       95%
  ├── 求导法则       90%
  ├── 单调性         52%
  └── 极值           38%
那么复习系统应该自动生成：
今日复习
│
├── 极值基础题 × 3
├── 单调性基础题 × 2
├── 导数综合题 × 1
└── 已掌握知识点 × 0
而不是简单：
哪道题到期了就复习哪道题。
十一、建议建立“知识点掌握度模型”
现在已经有：
tags
knowledge_points
review_logs
mastery
所以基础其实已经有了。
可以进一步计算：
Mastery(K)
=
f(
  最近正确率,
  连续正确次数,
  最近复习时间,
  SM-2 ease,
  题目难度,
  错误次数,
  遗忘时间
)
最终形成：
数学能力画像
比如：
代数       █████████░ 90%
函数       ███████░░░ 72%
导数       █████░░░░░ 51%
积分       ████░░░░░░ 43%
概率       ████████░░ 80%
然后 AI 自动生成：
本周建议重点复习：积分、导数。
这会比现在的“学情看板”有价值很多。

二十六、第十二优先级：增加“题目难度校准”
