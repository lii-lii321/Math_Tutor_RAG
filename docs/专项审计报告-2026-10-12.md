## 一、结论总览

**未发现 P0 级（数据丢失 / 未授权角色可越权 / 证书密钥泄漏类）已确认缺陷。** 核心防御线（JWT + token_version 吊销、工具归属绑定、zip slip 防护、备份幂等、限流、默认凭据告警）均在位且有测试覆盖。已确认缺陷集中在「教师多租户范围的双口径不一致」与「async 端点阻塞事件循环」两处 P1，以及两处 P2。

### 与任务书逐条对照的「已达标」项（审计确认，无需改动）

- **任务 A（检索）**：Keyword Top-N（SQL 下推）→ Dense 深候选池 → RRF 融合 → Hydrate → 可选 Rerank（失败降级融合序）→ 阈值过滤（只滤向量路独有候选）→ 末端分页（`question_mixins.py:426-571`），执行顺序、权限过滤（ChromaDB `where user_id $in` + hydrate 属主校验双保险）、降级路径（向量库故障→关键词）均正确；金标集门禁三测试（关键词 Recall@1 满分 / 混合 Recall@3≥0.6 / 关键词不丢）真实生效。评测实验对照（关键词 vs 向量 vs RRF vs reranker 分组指标）已在 `scripts/eval_retrieval.py` 提供骨架。
- **任务 B（数学验证）**：verified/failed/uncertain 三态显式区分（`math_verifier/models.py`），failed 一票否决、验证器异常留痕遥测（v2.11 教训注释）、uncertain 在 UI 明确提示「无法自动验证，请人工确认」（`frontend/components.py:80-82`）——「unknown 被当正确答案」的担忧不成立。覆盖面确实只有解代入 + 导数互逆两类（几何证明/分类讨论/应用题建模不可自动判定，靠 uncertain 兜底），这是已知边界而非缺陷。
- **任务 C（Agent）**：工具全部强制 user_id 归属绑定（`agent_tools.py:58`）、工具轮上限 8、会话历史上界裁剪（含孤儿 tool 消息保护）、引用 ID 校验（本轮工具结果白名单）、对话持久化属主校验（`conversation_service.py:40`）、SSE 端点为同步 `def`（FastAPI 线程池执行，不阻塞事件循环）。SM-2 调度纯函数、有单测。教学闭环（诊断→干预→变式→复测→记录）属于新能力建设，不在本轮「修复」范围，见 §七。
- **任务 D（工程/安全）**：完整备份导入已有 zip slip 防护、format/version 校验、逐条值域校验跳过、image_hash + 内容指纹双幂等、图片按新属主重生成 key（`full_backup.py` 文档块声明并实现）；DB↔ChromaDB 一致性有 `data_health` 体检 + 修复（缺失/残留/孤儿图三类）；班级成员变更即时生效（每请求实时查询 `student_ids_for_teacher`）；作业有取消属主校验 + 卡死回收；`.env` 未入库（gitignore 验证）；历史大 blob 问题已在上轮提交记录中明确「改写历史另行决策」。

## 三、未解决问题与后续建议（按价值排序）

1. **教学闭环 MVP（新能力，非修复）**：选一个真实知识点（建议二次函数），打通「诊断（掌握度+错因）→ 干预（讲解+变式）→ 独立作答验证 → 延迟复测 → 干预记录入档」。数据模型上复用现有 mastery/review 表即可起步，避免新建平行模块。
2. **金标集扩展为四类检索意图**：现有 12 条全部是「同一道题命中」型；按任务书补「同知识点不同题 / 同错因 / 同解法」三类人工确认样本，每类 ≥8 条，再谈 reranker/元数据过滤的分组对照实验（`scripts/eval_retrieval.py` 已有指标骨架：Recall@K / MRR / NDCG）。
3. **教师范围口径统一**（R1）：先定产品语义（建班教师的所有教师视图是否一律按班级收紧），再统一 dashboard_stats / 检索 / 导出三处。
4. **Agent 写操作服务端确认门**（R3）+ **工具错误分类**（R4）：多租户开放 Agent 前完成。
5. **评测独立性**：`scripts/eval_tutor.py` 已诚实声明自评偏乐观并检查必需工具命中；下一步补固定预期答案断言 + 人工抽检样本表。
