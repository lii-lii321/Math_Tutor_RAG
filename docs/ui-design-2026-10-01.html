MathMaster Edu · 界面重设计方案

从「功能平铺」走向「任务驱动」—— 一次针对信息架构、视觉层级与交互密度的整体重做

v1.0 设计稿 2026-10-01 范围：4 个核心页面 + 全局设计系统 落地方式：Streamlit CSS + 组件重排

00一句话结论

现有界面的问题不在配色，而在信息架构。MUJI 配色本身是干净耐看的，但九个平级菜单、 六个等权重图表、以及占满首屏的筛选器，把「今天该干什么」这个唯一重要的问题淹没在了功能列表里。 本方案不改品牌色，只改层级、密度与顺序。

P0 · 体验事故

复习页直接崩溃

截图 docs/screenshots/review.png 显示， 图片读取失败时整个 Python traceback 被原样渲染到闪卡上。 根因是 frontend/pages/review.py:101 直接 st.image()，且图片路径存的是另一台机器的绝对路径。 这是唯一必须立刻修的。

P1 · 效率损失

错题本要滚过一屏才看到题

五个 toggle + 两个下拉 + 搜索框组成的筛选区占掉首屏约 60%， 真正的题目列表被推到折叠线以下。分页器还放在了列表上方，视线要来回跳。

P1 · 决策缺失

看板给数据不给结论

六个图表（知识点分布 / 薄弱知识点 / 录入趋势 / 学习日历 / 正确率 / 难度）纵向平铺， 全部同权重。学生看到「18 道待复习」之后，不知道先做哪一道。

逐条问题清单

P0 没有错误边界

任何 IO 异常都会把 Python traceback 渲染到页面上。st.image()、service.*() 全无 try 包裹，用户看到的是开发者信息，不是产品信息。

P0 图片路径不可移植

数据库里存的是 C:\Users\liyun\.zcode\workspace\... 绝对路径， 换机器即失效。截图里已经在报错。

P1 导航无主次

九个菜单平铺，「AI 录题」（核心动作）与「设置」（低频）视觉权重相同。 没有"今天该做什么"的入口。

P1 筛选器吃掉首屏

错题本首屏 60% 是筛选项。5 个 toggle 并排堆叠，视觉噪音大且默认全关，等于白占空间。

P1 列表项信息无分层

expander 标题把到期标记、星标、标签、难度、日期、掌握度、未读批注共 7 类信息 串成一行纯文本，扫读成本极高。

P1 图表等权重平铺

六个 Plotly 图同尺寸同位置堆叠，看板纵向长到需要大量滚动，核心指标被稀释。

P2 语言不统一

难度直出 easy / medium / hard，角色直出 student， 导航曾在 i18n 里写成 "Ai 录题"（现已修为 "AI 录题"）。

P2 深色模式是覆盖式

frontend/theme.py 用 20 条 !important 逐个组件打补丁， 组件增加后必然漏改。应该改成 CSS 变量双套。

02四条设计原则

这四条决定了后面所有取舍。改版过程中如果出现冲突，按优先级从上往下判。

原则 1 任务优先于功能

用户打开应用的第一问是「今天该复习什么」，不是「这个应用有哪些功能」。 看板第一屏必须给出可执行的下一步，而不是一堆数字。 功能入口退居侧边栏。

原则 2 数据必须可扫读

一行文本里超过 3 类信息就该拆开。掌握度用色环+颜色编码， 状态用图标，颜色只承载一个含义（红=薄弱 / 琥珀=待复习 / 绿=已掌握）。

原则 3 默认折叠次要

筛选项、导出格式、难度分布这类低频操作不该常驻。 收进抽屉或 ⋯ 菜单，用 chip 显式回显当前生效的条件。

原则 4 保留 MUJI 骨相

现有配色克制、无紫、无炫技动效，这个判断是对的，本方案予以保留。 改的是层级与密度，不是审美口味。

03设计系统升级

现有 frontend/assets/style.css 的变量体系是对的，缺的是语义色层和深色模式变量对。 以下 token 全部可以平移到现有 CSS，不需要重写。

3.1 色彩：新增三档掌握度语义色

Token值语义
--navy#16294a品牌深色：标题、Hero、主按钮底色（较原 #1a365d 略深，压得住大色块）
--brand#2563eb交互蓝：可点击元素、当前选中态、进度
--weak#dc2626新增 薄弱（掌握度 < 50%）——与后端 WEAK_THRESHOLD 同源
--shaky#d97706新增 不稳固（50%–75%）/ 待复习——与 SHAKY_THRESHOLD 同源
--good#059669新增 已掌握（> 75%）/ 验证通过
--bg#f7f8fa页面底色（较 #f8fafc 略暖，接近纸张）
关键约束：三档色只用于表达掌握度/状态，不用于装饰。 一个界面上红色出现超过 3 处，就说明层级出了问题 —— 应该把它折叠进「薄弱」筛选里，而不是全量铺开。

3.2 深色模式：从覆盖式改为变量对

现状 · 20 条 !important 逐个打补丁
新增组件 → 忘记加规则 → 深色下变白底黑字
方案 · 一套变量，双主题
:root { --card:#fff; --ink:#1f2937; --line:#e5e7eb; }
[data-theme="dark"] {
  --card:#1a2333; --ink:#e2e8f0; --line:#2d3a4f;
}
新组件只用变量 → 自动适配双主题

05落地路径

以下是设计稿到 Streamlit 代码的映射关系。设计稿只到「长什么样」，具体怎么写由你决定。

5.1 改动量估算

阶段内容工作量说明
第一批 错误边界 + 图片路径修复 小 纯防御性代码，不改任何视觉。可独立先合，解决 P0。
第二批 CSS 变量化 + 三档语义色 中 改 style.css 与 theme.py，不碰页面逻辑。收益立竿见影。
第三批 侧边栏分组 + 今日复习红点 中 改 app.py 与 nav.py，需新增一个 due 计数查询。
第四批 看板重排（行动卡 + metric 条） 中 纯 st.markdown 重排，后端数据已够用（stats 已返回所需字段）。
第五批 错题本卡片网格 + 工具条 大 需要新的卡片渲染函数，筛选器从 toggle 改为 popover。改动最重但收益最大。
第六批 录题页结构化结果卡 中 解析结果本就是固定五段结构，拆成卡片即可。

5.2 Streamlit 实现要点

能做到的

  • 全部视觉：卡片、metric 条、chip、色环 —— 纯 CSS + st.markdown
  • 色环进度用内联 SVG（见本稿示例）
  • 折叠区用 st.expander 或原生 <details>
  • 工具条用 st.popover 做筛选抽屉
  • 评分按钮的「下次 N 天后」可由现有 SM-2 函数直接算出，无需新后端

需要权衡的

  • 错题本卡片网格：Streamlit 的 st.image 无法 hover 出操作层，勾选框需另想办法（可用 st.checkbox 置于卡片顶部）
  • 底部常驻操作条：position: sticky 在 Streamlit 容器里不完全可靠，可能需要 components.html 模拟
  • 卡片点击展开详情：网格视图下建议点卡片跳转到独立详情页，而非原位展开

5.3 配套的技术债

P1 图片路径建议改为相对路径

当前入库的是绝对路径，换机器必然失效。落库时改存 data/images/xxx.jpg 这样的相对路径，读取时用 pathlib.Path(__file__).parent.parent / image_path 拼接。 这个修复本身和 UI 无关，但不做的话新 UI 一样会崩。
