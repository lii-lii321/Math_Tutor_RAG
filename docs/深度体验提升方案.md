> 版本 v1.0 · 2026-10-02 · 基线 v2.12.0（353 tests / 5 E2E / ruff clean / 覆盖率实测 80%）
> 方法：以真实用户旅程为轴（录题 → 复习 → 检索 → 复盘 → 长期坚持），每个问题标注代码位置，

## 1. 体验问题全景（按用户旅程五幕）

### 第一幕：录入（拍题/Word）
- **上传区 40px 原生控件**，与"主入口"地位不符（tutor.py:25）
- 解析中无进度感：批量上传时只有 spinner，**逐题状态不可见、中途刷新全丢**
- 解析结果是一整块 Markdown：考点/讲解/答案/易错/变式混在一起，扫读成本高
- **异常无边界**：DB 挂掉时登录页直接打 traceback（auth.py:57/:90 已包，但上传解析链路仍裸奔）

### 第二幕：复习
- 评分按钮只有表情+文字，**决策成本高**（不知道选了之后间隔变成几天——预览 caption 已有但太弱）
- 未 reveal 时评分区塌陷，翻页高度跳动
- 进度条已改按已完成数（✅ 本批修复）
- 队列驻留已做（✅ again 当轮重现、撤销已做）

### 第三幕：检索
- 筛选区占首屏约 60%（5 toggle + 2 下拉 + 搜索框常驻，默认全关=白占空间）
- 当前生效的筛选条件**不可见**（用户不知道自己在什么视图里）
- 列表行塞 7 类信息（到期/星标/标签/难度/日期/掌握度/批注），扫读成本极高

### 第四幕：复盘
- 看板 v2 已重做（✅ Hero 卡/队列/分段条/环形图）
- 图表仍 6 个平铺在低优先级页；深色模式下 Plotly 内联色未适配

### 第五幕：长期坚持
- 激励只有连续天数一行字 + 复习完成气球
- 无每日目标、无里程碑、无到期主动提醒
- 数据资产弱：备份不含图片/进度、无 Anki/CSV 导出给第三方

## 2. 六大提升专项

### 专项 A · 交互可靠性收口（P0，约 1 天）
> 原则：任何用户动作都不应看到 traceback；任何等待都应有 spinner 与可取消。

| # | 项 | 位置 | 方案 | 验收 |
|---|---|---|---|---|
| A1 | 裸调用收口 | assistant.py:20/31/40、notebook.py:110/121、settings.py:171/184/206/215 | 统一 safe_call 包裹，失败转 error_card | 模拟 DB 断开，7 页均显示降级卡 |
| A2 | 上传解析链路兜底 | tutor.py 上传→解析→入库链 | safe_call 包裹 + 中途异常保留已上传文件可重试 | 断网解析失败后文件仍在、可重试 |
| A3 | settings 导出惰性化 | settings.py:223 每次渲染无条件全量导出 | 改为按钮触发生成 + session_state 缓存 | 打开设置页不再触发全量扫描 |
| A4 | 空状态原语 | 全站 4 种写法 | empty_state(icon, title, action) 收敛，空状态必须给下一步动作 | 全站空状态只有一种视觉 |

### 专项 B · 任务流顺滑（P1，约 2 天）
| # | 项 | 方案 | 验收 |
|---|---|---|---|
| B1 | 录题两栏改版 | 左=上传/选项，右=逐题状态缩略图+五段结构化结果卡（考点/讲解/答案/易错/变式各一卡）；解析中显示 62% 进度可恢复 | 上传 3 张图，能看到逐题状态与结果卡 |
| B2 | st.fragment 消灭整页重算 | 评分卡片区（进度头部/进度条/题卡/解析/评分/跳过/改题表单）包 `@st.fragment`——「显示解析」「跳过」只重跑片段；评分保留整页 rerun 保侧边栏徽标准确 | 点显示解析/跳过时侧边栏不闪（v2.14.0：0→1（评分卡片区），队列行/批量操作条延后批次） |
| B3 | 筛选进 URL | 筛选/页码写入 st.query_params，刷新/分享不丢状态；chip 回显当前生效筛选。分享边界：同账号带参 URL 结果一致；跨账号仅 keyword/tag 内容性筛选有意义（student 教师专属，掌握度/复习态筛选依赖个人数据）。生命周期：离开错题本即清 URL 与筛选会话态（再进为默认视图）；带参 URL 未登录新窗口打开 → 登录 → 进错题本筛选仍生效（穿登录可达） | 带筛选的 URL 发给他人打开结果一致 |
| B4 | 错题本列表分层 | 一行 7 类信息拆为四层：标题行（摘要）/元信息行（pill 徽章）/内容预览/操作行 | 手机宽度 375px 下不换行错乱 |
| B5 | 全局搜索 | 顶栏搜索框跳错题本并预填关键词（query_params 已支持） | 任意页搜索一次直达错题本结果 |

### 专项 C · 反馈与激励（P1，约 1 天）

## 4. 明确不做（边界）

- **不换前端框架**：留在 Streamlit，把 st.fragment/query_params 两大红利吃完
- **不做 WCAG 全合规**：焦点管理/ARIA 在框架手里，成本收益不匹配
- **不做虚拟滚动**：分页已解决千条卡顿
- **不改后端契约/schema/AI provider 抽象/RAG 融合逻辑**（与 UI 重设计方案 v1 边界一致）
