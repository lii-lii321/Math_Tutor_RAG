批 6 起点：错题本

notebook.py 400 行一行未改。动手前必须先解决下面这个功能性缺陷, 否则后面的批量操作都建不起来。

先修：批量选择当前是失效的。
notebook.py:233 的 selected_ids 是函数局部变量，每轮 rerun 重建。 而勾选框 notebook.py:266 嵌在 with st.expander(...) 内部 —— 只有当时处于展开状态的那 8 个 checkbox 会被实例化。
后果: 用户展开第一张卡、勾选、切到第二张卡, 第一张的选择立即消失; 一个都没展开时 selected_ids 恒为空, 批量操作条永远不出现。
修法: 勾选框移出 expander, 改用 st.session_state["sel_{id}"] 持状态, 底部操作条改为常驻渲染（按选中数决定是否展开按钮组）。
目标态 —— 工具条 + chip 回显 + 三列缩略图卡片 + 常驻批量操作条
落点规格
notebook.py:259-267 元数据现在全部拼进 expander_title 字符串（到期标记 / 星标 / 标签 / 难度 / 日期 / 掌握度 / 未读 7 类信息挤一行）。 规格: 拆成卡片四层 —— 缩略图 / 标签组 / 掌握度色环 / 到期状态。掌握度用 mastery_color()。
notebook.py:38-177 筛选区（5 个 toggle + 2 个下拉 + 搜索框）占首屏约 60%。 规格: 收成一行工具条 —— 搜索框 + 视图切换 + st.popover 筛选抽屉 + ⋯ 导出菜单。 当前生效条件用 chip 回显, 取代三个大导出按钮。
notebook.py:95-96 col_export 是个只塞了 <br> 的空占位列, 删掉。
notebook.py:269-309 批量条在列表之后条件渲染, 每次 rerun 重建 6 个按钮。 规格: 改常驻底部条 + st.session_state 持选择状态（见上方红框）。
notebook.py:215-231 分页器在列表上方, 视线要来回跳。规格: 移到列表下方, 补充"命中 N 题 / 每页条数"。
Streamlit 能力边界（动手前要接受的三条）：
  1. st.image 只输出图片节点, 没有 HTML 包裹与 hover 层。卡片上的悬浮操作按钮做不出来, 勾选框必须占据静态位置。
  2. 网格可用 st.columns, 但每张卡的独立按钮/勾选会各自占垂直空间, 与"卡片等高"冲突 —— 需接受一定的高度参差, 或改为固定行高的纯展示卡 + 单独操作区。
  3. 点卡片展开详情会让页面高度剧烈跳动, 建议改为跳独立详情页。
06

需要拍板的两件事

这两项不定, 后面会返工。

6.1　掌握度以哪套口径为准

项目里两套口径并存: 一套是掌握度引擎（backend/services/mastery.py, 复习日志时间加权 + 遗忘衰减, 阈值 0.4 / 0.7）; 另一套是看板的标签级启发式估算 （复习表现 + 调度间隔的看板口径）。用户可见的数据会不自洽。

建议：以引擎为准。 理由是引擎有时间加权与遗忘衰减, 能反映"三天没复习"这件事, 启发式做不到。代价是要改看板的统计查询 —— 但那本来就是 stats.py 里的一个方法, 改动范围可控。

注意这一步的顺序：口径没定之前不要做 mastery_color() 的全站替换 —— 换色是低成本的, 换口径是可能牵动看板/画像/图谱三处的。先定口径, 再统一颜色。

6.2　深色模式是继续打补丁, 还是推倒做变量对

现状是 :root, .stApp 整块重定义 + 20 余条 !important 组件补丁。 每加一个新组件就要记得加一条, 漏了就白底黑字。

建议: 先补语义色变量（第 03 节第 6 项，一行的事），暂不推倒。 推倒做 [data-theme] 变量对的收益是"以后不用打补丁", 成本是要把所有组件的硬编码色值改成变量引用 —— 在批 5 页面重排还没做完之前做这个, 会和页面改动搅在一起, 不好回归。

建议顺序: 批 5 页面重排完成 → 所有页面稳定后 → 再做一次纯深色模式重构。 那时改动面固定, 一次到位。
