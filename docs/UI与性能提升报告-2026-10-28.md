## 一、性能：「反映慢」的根因与修复

**测量方法**：`data/ui_design/perf_probe.py`（进程内直调服务层，每项 5 次取中位；语义路预热一次，冷启动单列）。修复前后同一脚本同口径。

### 根因（修复前实测）

| # | 位置 | 实测 | 根因 |
|---|---|---|---|
| 1 | 错题本每次 rerun 全量重生成导出 | **254ms/次**（18 题）、397ms/次（63 题） | 页面上 4 个 st.download_button 要求每次渲染都备好 Word×2/PDF/Anki 整册字节流——翻页、排序、任意交互都触发全量重生成。这就是「反映慢」的主凶，与热路径 P50 259ms 吻合 |
| 2 | 同帧重复查询 | 到期池在侧边栏徽标与看板各查一次 | 侧边栏先于页面渲染，结果没有共享通道 |
| 3 | 语义首查 | **2490ms 冷启动**（Chroma 挂载 + ONNX 模型加载）+ 每个新查询文本 ~230ms 嵌入推理 | 模型层成本（本地 MiniLM ONNX） |

### 修复（不动算法）

| 修复 | 实现 | 效果 |
|---|---|---|
| **导出产物进程级缓存**（新 `backend/services/export_cache.py`） | 缓存键 = 导出参数 + 当日日期 + 全量题面内容指纹（含 image_hash）；内容未变的 rerun 零生成成本，跨日自动失效，生成逻辑零改动 | 错题本任意交互的 rerun 消掉 ~254-397ms |
| 同帧到期池共享（app.py） | 侧边栏查询结果写入 `_frame_due_list`，同一次 rerun 内看板直接复用 | 每次看板 rerun 少一次全量查询 |
| RAG 后台预热 | 启动后异步挂载 Chroma + 预热嵌入模型（实测 3008ms） | 用户首次语义搜索不再吃冷启动 |
| 关键词候选池自适应扩池等（此前已提交 b330914） | 池打满扩池 ×10 | 混合路老题不再丢失 |

### 修复后实测（同探针）

| 服务方法 | 修复后 P50 |
|---|---|
| dashboard_stats | **5.5ms** |
| list_questions（语义，预热后） | **4.9ms**（其中嵌入 2.4ms + SQL/融合 2.5ms） |
| list_questions（纯关键词） | **1.0ms** |
| mastery_profile | 3.6ms |
| due_questions | 1.4ms |

**诚实边界**：每个「新」查询文本的语义嵌入仍是 ~230ms（ONNX 推理，模型层成本）——只有接入远程嵌入 API（`EMBEDDING_BASE_URL`，BGE-M3 实验）才能消掉；dashboard_stats 内部拆解显示各统计函数全部 ≤2.4ms，页面层无隐藏热点。

## 二、UI：新视觉体系

**设计规范**：`data/ui_design/spec.md`（MUJI 克制风 v3）+ `data/ui_design/tokens.css`。要点：

- **令牌单一真源**：`--weak/--shaky/--good`、`--navy/--slate` 等既有变量全保留（页面内联样式与测试断言依赖），新增完整色板/字体/间距/圆角令牌，深色模式 `[data-theme=dark]` 对应变量段；
- **橙退役**：品牌强调 = 蓝且仅蓝；警告 = 琥珀（≈--shaky）、破坏 = 红、无数据 = 灰；
- **一套卡原语**：`st.container(border=True)` 与 `.mm-card` 同一样式，深色只换变量；
- **兼容红线遵守**：`mm-badge` 系列类名、控件 key、按钮文案全部未动（`tests/test_ui_primitives.py` 等测试钉死）。

**实施范围**：17 个文件（style.css 重写、theme.py 主题与 Plotly 联动、全部页面样式类调整），+1054/-352 行。功能行为零变化。

### 复审发现并已修复的回归

- **看板队列行显示字面星号**（`**** 【演示模式】**`）：实施员在 markdown 串里混入 HTML 标记后，Streamlit 不再处理 `**` 粗体——已改为 `<strong>` + 用户内容转义（与此前 XSS 修复同纪律），门禁复跑全绿。
